# Ignition v0.3.3

Ignition's YOLO containers are now more accurate than AMD's Ryzen AI stack on the same quantized models. The README and usage notes compile YOLOv8n, YOLOv8s and YOLOv8n-pose with ignite-xdna's `--silu-sigmoid`, which computes each SiLU activation with a four-line integer sigmoid on the NPU instead of the HardSigmoid form AMD's XINT8 model uses. YOLOv8n and YOLOv8n-pose stay faster end to end than AMD's stack. The ignite-xdna wheel attached here is 0.3.1; the `npu` extra now requires it.

## What changed

- **A closer SiLU on the NPU.** `ignite-compile --silu-sigmoid` gives every SiLU a four-line integer sigmoid that the NPU's core program applies after each convolution pass; every layer matches an integer reference model of that form, and containers compiled without the flag are unchanged (ignite-xdna `45a8685`, `7700316`). The README's YOLOv8n command and the usage notes' YOLOv8s and YOLOv8n-pose commands add it. It needs no requantization. SESR M7 has no SiLU, and the compiler refuses the flag for a container with a CPU step, such as YOLO11n.
- **Detection heads read in place.** ignite-xdna reads YOLO's detection heads where the NPU wrote them, one sync per run of adjacent heads, and decodes them without copying them into NCHW order; the detections are identical to the previous decode (ignite-xdna `8285f78`, verified in `1879614`).
- **SESR M7's host work in native code.** Its resize and image output run in native code, 2.05 ms less per frame. The native resize is within one code of OpenCV's, but the output image differs from the OpenCV path's (41.42–42.19 dB PSNR between them).
- **Power modes reach YOLO11n's CPU step, and the NPU power switch ships.** ignite-xdna 0.3.1 is the first release with `fbd53f5`, which puts the ONNX Runtime threads of a container's CPU step under `--power-mode`, and with `pipelines/npu_power.py`, behind `--npu-power`.
- **Documentation.** Every AMD comparison in the performance notes and every latency badge was re-measured on these containers; new badges show COCO accuracy against AMD's stack.

## Known limitations

- The NPU path needs an AMD Phoenix NPU (XDNA1) on Windows 11 with AMD's NPU driver, and a Python where the XRT SDK's `pyxrt` imports (3.13 on the test machine). Hawk Point is untested; Strix-class NPUs and Linux are not supported.
- No `.ignite` container is attached. Building one needs an ignite-xdna checkout and the mlir-aie toolchain, which `install.ps1` sets up.
- AMD's stack is faster on YOLOv8s and on SESR M7, and `--silu-sigmoid` widens the YOLOv8s gap to 1.43 ms; compile YOLOv8s without the flag to keep 0.34–0.39 ms.
- Energy per frame has not been measured on the `--silu-sigmoid` containers. An attempt at 30 fps was discarded because the host's idle power was not clean; the energy figures and badges in the performance notes are from the containers without the flag.
- YOLO11n's attention core runs on the CPU, and its COCO accuracy through the container has not been measured.
