# Ignition v0.3.2

Ignition now spends less energy per frame than AMD's Ryzen AI stack at a camera's 30 frames per second, and lets you choose how much CPU power it uses for speed. It also runs YOLOv8s, SESR M7, YOLOv8n-pose and stock YOLO11n on the NPU, decodes boxes in native code, and installs with one PowerShell command. The ignite-xdna wheel attached here is 0.3.0; the `npu` extra now requires it.

## What changed

- **Power modes, and a fix for a CPU that never idled.** Every NPU run before this release kept all of the processor's threads spinning between frames: ignite-xdna's native preprocessor asked its OpenMP threads to sleep, and the request never reached MSVC's OpenMP runtime. ignite-xdna 0.3.0 fixes that and adds three modes sized to your processor's own cores, which `live_ignition.py` / `python -m ignition.live` and `ignition suite` select with `--power-mode`: `performance` keeps the threads spinning on every logical processor, `balanced` (the default) lets them sleep between frames with one per physical core, and `efficiency` sleeps them with a quarter of the physical cores. `--max-fps` paces the loop the way a camera delivers frames (`2f27a74`, ignite-xdna `3bfebcd`).
- **Model zoo.** `--task` serves detection, classification, super-resolution and pose models, read from the container manifest or the ONNX outputs; YOLOv8s and SESR M7 containers run on the NPU (`e5f7d83`, ignite-xdna `6bd2718`). `ignition suite` runs several models, one process and JSON record each, and the app moved into the package as `ignition.live` (`f9c85fb`).
- **YOLO11n with its attention block.** Stock YOLO11n runs with its convolutions on the NPU and only its attention core (two matrix multiplies and a softmax) on ONNX Runtime's CPU provider (`50c341d`, `8305de3`, ignite-xdna `0be9132`, `d223e7b`).
- **YOLOv8n-pose.** Pose containers run all 75 layers on the NPU and the app draws each person's skeleton (`5564554`, ignite-xdna `c762c0e`).
- **Native box decode.** DFL decode and NMS for the NPU's heads run in native C, with detections identical to the numpy path (ignite-xdna `e2867b6`; the README's AMD comparison re-run on it in `ffdefad`).
- **Backends and camera.** An `.onnx` model runs on ONNX Runtime's CPU provider with no NPU call, and `ignition devices` prints only what `pyxrt` reports (`7a09e6d`); the app measures the webcam's distinct frame rate and can turn exposure auto priority off (`b8fac98`).
- **Install and documentation.** `install.ps1` installs or updates the NPU path from one PowerShell paste (`6985ef7`); the README walks from it to a running container in under 250 words, with badges that each compare Ignition with AMD's stack (`f91d0db`, `d3c3e93`); `docs/QUANTIZATION-GUIDE.md` covers designing models for this NPU (`46034ce`, `31e8b99`).

## Known limitations

- The NPU path needs an AMD Phoenix NPU (XDNA1) on Windows 11 with AMD's NPU driver, and a Python where the XRT SDK's `pyxrt` imports (3.13 on the test machine). Hawk Point is untested; Strix-class NPUs and Linux are not supported.
- No `.ignite` container is attached. Building one needs an ignite-xdna checkout and the mlir-aie toolchain, which `install.ps1` sets up.
- AMD's stack is faster on YOLOv8s and on SESR M7. For YOLOv8s every runtime-side change tried in ignite-xdna was measured and none closed the gap, so it is recorded there as a known limitation.
- Energy has been measured on YOLOv8n only, and the power modes, though sized to each host's cores, only on the 8-core, 16-thread Ryzen 7 8700G.
- YOLO11n's attention core runs on the CPU, and its COCO accuracy through the container has not been measured.
