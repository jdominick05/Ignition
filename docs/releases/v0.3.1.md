# Ignition v0.3.1

Ignition now runs the whole YOLOv8n network on the AMD Phoenix NPU from an ignite-xdna `.ignite` container, and the wheels on this page install with pip: the CPU path on its own, the NPU path together with ignite-xdna's wheel. This is the first release since v0.2.0; version 0.3.0 was never published.

## What changed

- **Native NPU path.** `.ignite` containers built by ignite-xdna run all 66 YOLOv8n layers on NPU Device 0. Boxes are decoded from the NPU's detect heads and ONNX Runtime is not called (`ee66fbd`). `.onnx` models still run on ONNX Runtime's CPU execution provider.
- **Webcam app.** `live_ignition.py` in the repository opens a webcam, video or image and reports glass-to-glass latency percentiles (`ee66fbd`, `8ffa482`). It is not part of the wheel.
- **pip install works.** ignite-xdna is now the optional `npu` extra, so installing the Ignition wheel no longer fails on a dependency that is on no package index (`60a7be1`). The ignite-xdna wheel attached here declares its own dependencies and ships its native ingress kernel (ignite-xdna `389f0a7`).
- **Documentation.** A README with a same-sitting comparison against AMD's Ryzen AI stack, a compatibility matrix and a performance table in which every row names its record (`f3fd2f0`, `13157f8`, `6100486`).

## Measured

Ryzen 7 8700G, NPU Device 0, Windows 11, 2026-09-14:

| Run | Result | Record |
|---|---|---|
| `live_ignition.py --headless --frames 300`, webcam, lit room | 7.89 ms mean, 8.39 ms 99th percentile, 5.43 objects per frame | README Performance table (`f3fd2f0`) |
| `bus.jpg`, 50 warm-up and 500 timed frames, runs alternated with AMD's stack | Ignition 8.09 / 8.27 ms mean; AMD Ryzen AI Software 1.7.1 (ONNX Runtime with the Vitis AI EP) 11.13 / 11.09 ms | README comparison (`13157f8`) |
| `bus.jpg`, 10 warm-up and 300 timed frames, from wheels installed with the `[npu]` command below | 8.051 ms mean, 5 detections per frame; editable checkouts in the same sitting 8.035 ms | commit messages of `60a7be1` and ignite-xdna `389f0a7` |

Ignition's lead over AMD's stack is in host-side code, image preparation and box decoding; AMD's NPU stage itself is about 0.8 ms faster. The README says what each figure counts.

## Corrections to v0.2.0

The v0.2.0 notes quoted fused-layer latency and throughput (168.37 µs, 5,919.6–6,107 FPS), a frame rate measured before the native `.ignite` path existed (27.39 FPS), and a ratio of the Ignition wheel to AMD's entire install (72,000×). None of them describes end-to-end detection in this release; use the figures above and in the README.

## Known limitations

- The NPU path needs an AMD Phoenix NPU (XDNA1) on Windows 11 with AMD's NPU driver, and a Python where the XRT SDK's `pyxrt` imports; only Python 3.13 has been tested with it. Hawk Point is untested; Strix-class NPUs and Linux are not supported.
- No `.ignite` container is attached. Building `build/yolov8n_full.ignite` needs an ignite-xdna checkout and the mlir-aie toolchain.
- On an `.onnx` model, `ignition.compile` and `ignition detect` default to `backend="xdna1"`, which adds an NPU call whose output is not used; pass `--backend cpu`.
- An installed ignite-xdna caches extracted xclbins under `<environment>/Lib/build/ignite_cache`.
